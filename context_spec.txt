# 本文件說明記帳對話的上下文視窗、摘要與記憶管理需求。
1. 滑動視窗法（Sliding Window）：
   - 限制只保留最近的 X 輪對話（X 可設定，預設為 5 輪，包含 User 與 Assistant 的對話共 10 筆）。
   - 每次有新對話時，自動淘汰掉最舊的對話，確保傳給 LLM 的對話長度不會無限膨脹。

2. 摘要法（Summarization）：
   - 當目前的對話歷史總 Token 數或歷史筆數超過設定的閾值時，觸發摘要機制。
   - 呼叫 LLM 把舊的對話（除了最近 2 輪以外的舊對話）濃縮成一段「使用者目前的記帳與理財狀況摘要」。
   - 將這個摘要放進 System Prompt 中（例如：「目前使用者的狀況是：[摘要內容]。請根據此狀況與接下來的對話互動」），然後清空被摘要掉的舊對話。

請幫我完成以下任務：
1. 根據上述需求，設計一個記憶管理器（Memory Manager）的類別（Class）或模組。
2. 設計適合儲存這些對話歷史與摘要的資料庫結構（如果是記憶體內實作，請用字典/陣列；如果要存資料庫，請提供 schema 建議）。
3. 寫出一個封裝好的函式，輸入「最新記帳留言」，就能自動處理記憶（判斷要用滑動視窗還是觸發摘要）、呼叫 LLM API，並回傳 LLM 的最新回覆。
