# 本文件說明記帳 Web App 的產品需求與技術架構規格
我想製作一個結合 Google Gemini API 的記帳網頁 APP。
為了方便本地運行、開發與未來部署，請採用以下技術棧：
- 前端：React + Tailwind CSS，使用 Vite 建立；前端只負責 UI 互動與呼叫後端 API。
- 後端：Python + FastAPI，負責本地資料儲存、花費計算，以及透過 Google GenAI Python SDK 對接 Gemini API。
- 本地資料庫：優先使用 SQLite；資料庫檔案留在本機，不提交 API 金鑰或個人資料至版本控制。
## 規格與架構要求
### 1. 獨立 LLM 服務模組
後端必須將 LLM 整合獨立成 Python 模組，例如 `llm_service.py`。由此模組負責建立 Gemini 請求、傳送 Prompt、解析結構化回應與處理 Gemini API 錯誤；其他後端程式透過清楚定義的函式呼叫它。日後更換其他 LLM 時，應盡量只需替換或新增服務模組，不需大幅改動資料庫、API 路由或前端。
使用 Google GenAI Python SDK（Python 套件名稱：`google-genai`）連接 Gemini API。API 金鑰只能由後端從環境變數 `GEMINI_API_KEY` 讀取，不得傳到前端、寫入原始碼或提交至 Git。模型名稱由 `GEMINI_MODEL` 環境變數設定，並提供合理的預設值，方便日後更換可用模型。
### 2. 資料儲存與參數定義
後端負責紀錄、查詢與計算，並提供 API 給前端取得下列數據：
- 今日總花費
- 本月總花費
- 本月大魔王支出：每月固定或大額支出，例如房租、電信費、保險等，由 LLM 分類
- 本月日常支出：大魔王支出以外的日常花費
使用 SQLite 儲存記帳資料，至少記錄每筆資料的唯一 ID、物品名稱、金額、日期、分類、該次留言及建立時間。金額須使用適當的數值型別；API 應依記帳日期計算今日與本月總額，並依分類計算本月大魔王與日常支出。分類結果及 AI 評論也應保存，讓重新啟動後端後資料仍存在。
### 3. 前端輸入介面與資料儲存
- 介面可新增一筆或多筆記帳，每筆至少包含：物品名稱、金額、日期。
- 提供獨立的留言區。
- 每次送出必須包含至少一筆記帳資料及一則留言；前端與後端都要驗證必填欄位及金額。
- 送出後由後端先保存資料，再計算並更新今日總花費、本月總花費及分類小計。
- 前端顯示送出結果、分類、AI 評論，以及更新後的統計數據。
- 若 Gemini API 未設定或呼叫失敗，記帳資料仍應保存在本地，並明確告知使用者 AI 分類／評論暫時不可用；不得因 AI 失敗而遺失記帳。
### 4. 後端 Prompt 包裝與 Gemini API 呼叫
後端收到前端送來的多筆記帳與留言後，先以後端資料庫計算本次請求及帳本的今日總花費、本月總花費，再由 `llm_service.py` 將下列內容包裝成 Prompt 並傳送給 Gemini API：
- 每筆記帳的唯一 ID、物品名稱、金額及日期
- 使用者留言
- 今日總花費與本月總花費
- 分類規則及 AI 評論要求
Prompt 要明確要求以繁體中文回覆，並將使用者輸入視為資料而非指令。不得將 API 金鑰交給模型或回傳前端。呼叫錯誤、逾時、空回應或格式不符時，後端需妥善處理並保留已保存的記帳資料。
### 5. AI 記帳結構化分類
- 使用 Python Pydantic 定義 Gemini 回應資料模型，並透過 Google GenAI SDK 的結構化輸出功能，要求 Gemini 依指定 JSON Schema 回應。
- 回應至少包含每筆記帳的 ID 與分類（`大魔王支出` 或 `日常支出`），以及 AI 評論文字。
- 後端驗證回應筆數、ID 是否與本次送出的記帳相符，以及分類是否為允許值；若驗證失敗，應回報 AI 分類失敗並保留資料，不能將未驗證內容當成有效分類。
- 結構化輸出可約束回應格式與欄位，但分類判斷仍是模型推論；遇到不確定或資訊不足的支出時，Prompt 應要求模型採用「日常支出」並避免過度推測。
- 驗證成功後，更新 SQLite 中的分類與 AI 評論；統計數據由後端根據資料庫即時計算，避免只依賴模型提供的總額。
### 6. AI 評論功能
LLM 根據本次記帳內容、使用者留言，以及今日與本月花費，產生一段簡短、友善、實用的繁體中文消費觀察或理財建議，並與分類結果一同回傳前端顯示。評論應避免批判、羞辱使用者或假裝提供專業投資／財務保證。
### 7. API 與專案交付
- 至少提供新增多筆記帳的 API，以及取得統計與近期記帳資料的 API。
- API 使用 Pydantic 定義請求與回應格式，並回傳清楚的錯誤訊息與適當 HTTP 狀態碼。
- 提供 `.env.example`，列出 `GEMINI_API_KEY`、`GEMINI_MODEL` 等設定名稱，但不得放入真實金鑰。
- 提供 Python 依賴清單（例如 `requirements.txt`）、前端 `package.json`、SQLite 初始化方式及清楚的本機啟動說明。
- 建議的完整專案結構至少包含 FastAPI 後端（API 路由、Pydantic schema、資料庫、`llm_service.py`）與 Vite 前端（React 主介面、樣式與 API 呼叫模組）。
請依本規格產出完整專案檔案結構、FastAPI 後端程式碼（包含 Pydantic 設定、SQLite 儲存與 Gemini API 對接），以及 React + Tailwind CSS 前端主介面程式碼，並說明每個檔案的用途、環境設定方式與本機啟動步驟。
